# RC7 production architecture options — design candidates, NOT configured
Identity: choose a managed OIDC issuer (candidate Microsoft Entra ID or Auth0) only after organization tenancy, pricing, MFA policy and administrative authority review. Validate server-side token signature with the issuer's current JWKS, exact issuer, audience, expiration, not-before, authorized tenant, role assignment, token revocation and key rotation. Treat client-submitted roles as untrusted. For high-impact actions enforce step-up authentication and a persistent, transactional one-time nonce store. RC7 only simulates expiration, synthetic roles and replay with a process-local set.
Evidence: candidate AWS S3 Object Lock Compliance mode with versioning, per-version retention, least-privilege bucket policies, encryption, independent account, verified retention receipt, object version IDs and off-account audit anchoring. Object Lock applies to versions; a simple delete marker may hide the latest version. Compliance mode and legal hold have different semantics. No AWS bucket, real lock, checkpoint publisher, or externally anchored digest exists in RC7.
Privacy: allowlisted synthetic public envelopes only. Actual sensitive case data must use authenticated encryption, explicit private/public separation, secure audit trail, deletion/retention policy review, and trained independent reviewers.
Legal: CEE and OCE are routing candidates, not legal determinations. Human legal review required for authority, standing and deadline before any referral.
Evidence: 2024 preliminary/canvass CSV index on electionspuertorico.org is THIRD PARTY; CEE originals still required for authoritative binding. PREKEY/UNIKEY/COLKEY are column names observed in the public documentation, not validated identities or complete counts.
No deployment, no real complaint processing, no federation registration, no source bulk downloads.
